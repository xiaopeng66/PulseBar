## 1. 阶段一：静态审查（不改代码，只读）

### 1.1 接线矩阵（D5，最重的表）

对 S5/S6 的每一个控件建立五行链路表，逐行打勾：

```
控件ID → 消息映射(ON_*) → 处理函数 → 改写哪个草稿字段 → CollectSettings 是否读取
→ ApplySettings 写到哪个 theApp 字段 → 副作用标志(is_*_changed) → SaveConfig 键名
→ LoadConfig 读回 → 运行时消费点
```

重点核对历史遗留坑：
- 每个字段“读控件初始化”与“CollectSettings 写回”必须成对；分区延迟初始化后
  （TaskBarSettingsDlg 的 EnsureSectionReady），未就绪控件的读取守卫是否完备。
- `m_notify_icon_selected`（0..3）与资源数组（0..2）的边界：所有 GetNotifyIcon 调用点。
- OptionsDlg 草稿（m_notify_icon_selected）与通用页/图标选择对话框的传递链。
- 消息映射里有处理函数但资源里已删控件、或反之（RC 与 resource.h 与 message map 三方对账）。

### 1.2 死代码与重复功能（D3）

- 资源模板中存在但从未被读取/写回的控件（接线矩阵里第五列为空的行）。
- 配置键存在但 UI 不可达、或 UI 项不落配置的孤儿键（对 config.ini 全键清单 × 代码读点对账）。
- 同一功能多处入口行为是否一致（托盘菜单“更换图标” vs 设置页图标选择）。
- `TODO/未实现/注释掉的功能块`清单化。

### 1.3 版本分支与死分支（D8）

- `IsWindows7/8/10/11`、`COMPILE_FOR_WINXP`、`IsTaskbarTransparent` 等分支逐个核对：
  低版本路径是否仍可编译、是否有已不可能触达的分支。
- `m_notify_icon_selected == NOTIFY_ICON_AUTO` 在 Win7/8 的固定深色语义与预览一致性。

### 1.4 并发与生命周期（D4/D7）

- WinHTTP 异步回调与 DLL 卸载（magpiebar 的 UNLOAD_NOTIFY_EVENT）。
- 图标句柄所有权（共享 LoadIcon vs 自建 HICON 的销毁归属）、TraySpeedIcon 缓存。
- 定时器清单（DELETE_NOTIFY_ICON_TIMER、TIMER_TEMP_NAMES、hover/selector 的 UI 定时器）
  的建立/销毁配对。

## 2. 阶段二：功能 bug 与边界专项（D4/D8）

按“输入×状态×时机”矩阵设计，全部先在隔离 fixture 验证，再上真机：

1. **配置畸形矩阵**：每个托盘/任务栏/通用键 × {空、非数字、越界、超长、重复键、
   BOM 缺失、CRLF/LF 混用、只读文件、JSON 损坏（history）} → 必须回落安全默认且可自愈。
2. **图标状态机**：静态⇄网速⇄临时通知⇄隐藏 的全部迁移路径 × NIM_ADD/MODIFY 失败注入 ×
   DPI 变化 × Explorer 重启（TaskBarCreated）× 主题切换；覆盖 0xc0000409 类 fail-fast 风险点。
3. **设置事务**：OK/Apply/Cancel 三路径 × （分区未访问/访问过 × 字体越界 × 便携模式切换 ×
   语言切换 × 更新源改动），验证“取消不落盘、Apply 幂等、OK 全量一致”。
4. **分区延迟初始化**：直接定位到分区 1/2 打开设置、快速连续切换、切换中改窗口尺寸/DPI、
   EnsureSectionReady 幂等、未就绪时 CollectSettings 不落默认值（回归已有断言）。
5. **magpiebar 边界**：网关不在/超时/返回 5xx/JSON 半截/供应商增删/端口被占；悬浮面板跨屏、
   任务栏自动隐藏、垂直任务栏、宿主重启时插件重载。
6. **系统事件**：睡眠唤醒、显示热插拔、主题深浅切换、任务栏对齐方式切换（居中/左侧）、
   多显示器主副切换、杀 Explorer。
7. **数据**：history_traffic.dat 损坏/超大、多实例并发写、便携模式目录迁移。

## 3. 阶段三：接线与功能的动态验证（D5/D6）

1. **控件全遍历脚本化验证**：为 S5/S6 每个可交互控件写一段隔离 fixture 操作
   （置值→CollectSettings→Apply→重读配置→断言），形成“控件覆盖表”，未覆盖控件即缺口。
2. **键盘可达性**：Tab 序（RC 资源里的 WS_TABSTOP 清点）、Enter/Esc 在子页的转发
   （CTabDlg::PreTranslateMessage）、下拉键盘操作、SpinEdit 焦点行为、助记键冲突。
3. **鼠标交互**：导航悬停绘制、分组框点击穿透、双击行为、滚轮作用域
   （SetControlMouseWheelEnable 的启用矩阵）、拖动排序阈值、tooltip 覆盖与失效。
4. **模态与焦点**：颜色对话框/字体对话框/自适配设置等二级对话框的父窗口关系；
   设置打开时主窗口定时器是否继续跑（采样是否停摆）。
5. **文案核对**：18 语言逐键抽查（含新增 IDS_PULSEBAR_ICON_AUTO）、Debug 后缀、
   阈值通知标题、tooltip 与实际行为一致。

## 4. 阶段四：视觉与空间排布审查（D1/D2，截图 + 评审）

1. **截图矩阵**（用隔离 fixture + 官方桌面工具截图，不碰真实配置）：
   - 设置对话框 6 分区 × {100%/125%/150% DPI × Win11 浅/深色 × 空配置/满配置}
   - 图标选择对话框 4 样式 × 预览左右半区
   - 任务栏窗口 × 主题 × 排列 × 图形模式；悬浮面板/选择面板 × 4/3/2/1 供应商
   - 托盘：三样式+自动 × 浅/深任务栏 × 96~288 DPI × 网速图上下半区
2. **评审标准**（每张截图按此打分，0–2 分，低于阈值记 P2/P3）：
   - 对齐：控件基线/列对齐是否落在统一网格；分组框内外边距是否一致
   - 密度：行距是否均匀，无过挤/过空；同类控件尺寸一致
   - 层次：标题/说明/值的字重与颜色层级清晰；禁用态可辨识
   - 一致性：同一语义（确定/取消/刷新/警告）在所有表面样式统一
   - 空间：窗口尺寸与内容匹配（无大片空白/裁切）；滚动条出现时机合理；
     折叠/展开（主题模式收起配色行）后无残影、无大洞
   - 图标：小尺寸（16px）可辨识度、深浅背景对比度、alpha 边缘无脏边、预乘正确
3. **人机流审查**：完成一个典型任务的点击次数与路径（改字体→改主题→看额度）；
   信息层级是否符合“常用在前、危险在后”；错误提示是否可操作（给出下一步）。
4. 评审执行：截图交给独立视觉评审（visual-judge）出具逐图判定，人工复核争议项。

## 5. 阶段五：性能与资源审查（D7）

1. 已有基线沿用：设置首屏 104 断言 + create_ms/create_cpu_ms（15.18 节数据）；
   新增目标——分区首次切换耗时、全分区遍历耗时。
2. 资源账本：GDI 对象数（速度图 200 次刷新 delta=0 已有）、USER 对象、窗口句柄、
   字体/位图/图标在反复开关设置、反复切换分区、反复刷新插件后的增量（≤ 阈值）。
3. 内存：宿主进程 8 小时挂机采样（工作集/提交）＋插件刷新循环的斜率。
4. 启动链：从进程创建到托盘就绪的分段计时（更新器/杀软干扰另记）。
5. 决策留痕：设置页打开若仍不满意，评估“任务栏页模板按分区拆三”的收益/风险
   （15.18.4 数据：~90ms HWND 创建是剩余大头）。
