## 编译与架构

1. 使用 Visual Studio 2022 的 C++ 桌面开发组件；采用 MFC 的插件还需要相应 MFC 组件和运行库。
2. 从仓库的 `PluginDemo/PluginDemo.vcxproj` 开始，引用本仓库 `include/PluginInterface.h`。
3. 选择和宿主匹配的架构。x64 DLL 不能加载到 x86 宿主；ARM64EC 是否可用还取决于插件及其依赖的实际构建与兼容性。
4. 发布插件 DLL 时说明宿主版本、架构、依赖、许可证和校验值；不要只发送 Debug 构建产物。

主程序的 `build-sln.bat` 只构建主程序目标；不应把它当作“已经构建并发布 PluginDemo”的证明。

## 入口与对象生命周期

宿主查找导出符号 **`TMPluginGetInstance`**，并取得一个 `ITMPlugin*`。

- 导出名应可被 `GetProcAddress(..., "TMPluginGetInstance")` 找到；使用未修饰的 C 导出或 `.def`，不要意外导出名字被修饰的符号。
- 返回对象必须在 DLL 保持加载期间有效，不能返回栈对象、临时对象或已经释放的对象。
- 使用 MFC 的 DLL 回调按示例切换 `AFX_MANAGE_STATE`，避免资源和模块状态错误。
- 不要在 `DllMain` 中执行网络、耗时扫描、弹窗或跨线程等待。

当前接口头文件默认 API 版本为 **8**。宿主按接口版本判断是否调用较新成员；这不是对任意未来 API 版本的兼容承诺。

## 显示项目

实现 `ITMPlugin::GetItem(index)`，按从 0 开始的索引返回 `IPluginItem*`，枚举结束必须返回 `nullptr`。

每个项目应提供：

| 成员 | 约束 |
| --- | --- |
| `GetItemId()` | 稳定、非空的持久化身份；不要每次启动或采样随机变化 |
| `GetItemName()` | 非空的项目名称，用于项目选择/管理 |
| `GetItemLableText()` | 返回有效字符串指针；可以返回空字符串以不画标签，但不能返回空指针 |
| `GetItemValueText()` / 示例中的取值成员 | 返回生命周期有效的文本；避免在绘制期间联网或进行长时间 I/O |
| 自绘宽度接口 | 使用合理非负宽度，按接口区分 DIP/实际像素；0 的回退语义请以接口和示例为准 |

宿主会对项目数量、非法元数据和自绘宽度限幅。**不要依赖宿主的防护来替代插件的正确实现**：一个在进程内运行的插件仍可能因坏指针、访问违规或锁错误影响整个程序。

## 选项、详情和自定义命令

### 选项

实现 `ShowOptionsDialog(void* hParent)`，将传入的 HWND 作为设置对话框 owner。返回：

- `OR_OPTION_CHANGED`：选项有更改，宿主需要更新相关显示；
- `OR_OPTION_UNCHANGED`：没有更改；
- `OR_OPTION_NOT_PROVIDED`：插件没有选项窗口。

不要自行查找其他正在运行的 PulseBar 实例，也不要在对话框关闭前释放其背后的插件对象。

### 详情

通过 `GetInfo(PluginInfoIndex)` 提供名称、描述、作者、版本、版权和项目 URL。URL 应指向插件作者实际维护的页面，不要使用不存在的占位仓库。

宿主读取返回的文本时会复制它，但插件仍应返回有效字符串。最安全的方式是为不同字段维护稳定存储，不返回已经失效的临时 `wstring::c_str()`。

### 自定义命令

按接口版本实现：

- `GetCommandCount()`；
- `GetCommandName(index)`；
- `GetCommandIcon(index)`；
- `IsCommandChecked(index)`；
- `OnPluginCommand(index, hWnd, para)`。

命令索引从 0 开始；名称和图标可以变化，但每次调用要保证其返回值有效。命令名称不应为空；无图标可返回 `nullptr`。

托盘根菜单直接显示插件名，名称下会组合“详细信息 / 选项 / 禁用”与插件实际公开的命令。宿主使用独立动作映射，不把其他插件的同名命令混到一起。当前对每插件最多枚举 257 个自定义命令，并受进程内动态 ID 容量约束；超出部分不会变成不受约束的命令 ID。

如果插件某功能只存在于选项窗口而没有通过命令接口公开，宿主不能自动推导它。希望功能直接出现在插件菜单时，应把它实现为命令。

## 线程与性能

- 数据采集回调与 UI 绘制/菜单回调可能位于不同线程。共享字符串、图像和状态应使用锁或不可变快照；不要返回另一个线程正在修改的缓冲区。
- 插件设置窗口、菜单和绘制属于 UI 路径，不能在其中做阻塞式下载、长扫描或无限重试。
- 不要在持有插件内部锁时同步回调宿主并等待宿主 UI；这可能形成死锁。
- 缓存耗时数据，采样时更新，绘制时读取稳定结果；不要因为宿主一次绘制而再启动采集线程。
- 宿主对部分 C++ 异常和非法返回进行了防御，这**不是** SEH/坏指针隔离或插件沙箱。

## 配置与卸载

支持相应 API 时，宿主通过 `OnExtenedInfo(EI_CONFIG_DIR, ...)` 提供插件配置目录。使用自己的命名空间和文件名，不覆盖主程序的 `config.ini`、历史流量或其他插件的数据。

“禁用”修改配置，重启后生效。当前不支持安全热卸载；不要在菜单操作中自行释放 DLL 或销毁宿主窗口。

## 发布前检查

- [ ] x64/x86 等目标架构与宿主一致，依赖齐全；
- [ ] 导出入口存在，返回对象和显示项目的生命周期正确；
- [ ] `GetItem()` 有正常终止，项目 ID 稳定且元数据不为空；
- [ ] 命令数量、索引、名称、勾选状态正确，多插件同时加载不串命令；
- [ ] 设置确认/取消、显示/隐藏、主题、字体、DPI、宽度变化无异常；
- [ ] 不在 UI 回调中阻塞，不产生数据竞争或死锁；
- [ ] 禁用、退出和重新启动不丢失插件配置；
- [ ] 下载页面真实存在，说明兼容性、依赖、许可证及校验值。
