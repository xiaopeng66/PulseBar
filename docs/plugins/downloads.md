# PulseBar 插件下载与安装

这是 **PulseBar 本仓库维护的插件入口**，对应软件“插件管理 → 更多插件下载”。开发接口与示例见 [插件开发指南](development.md)。

> 本页的直列插件菜单说明对应当前修复代码；尚未覆盖旧 V1.1.0 发行包。已安装版本的菜单可能仍有额外分类层，发行包是否更新以该版本的发布说明为准。

## 下载之前

- PulseBar 的版本与插件的版本是两回事。请先确认作者声明支持的宿主版本，以及 **x64 / x86 / ARM64EC** 架构。
- 插件 DLL 在 PulseBar **进程内执行**，不是沙箱程序。只安装你信任的作者发布的文件；不要为运行陌生插件关闭系统防护。
- 不要仅凭文件名判断安全或兼容。作者如果公布 SHA-256 或签名，下载后先核对。

## 当前可确认的发布渠道

| 项目 | 本仓库可确认的状态 | 入口 |
| --- | --- | --- |
| PulseBar 主程序 | 主程序的便携包/可执行文件，不等于插件下载包 | [正式发行版](https://github.com/xiaopeng66/PulseBar/releases) |
| PluginDemo | 本仓库提供的插件**源码示例**，未在主程序发行页单独发布预编译插件 DLL | [示例源码](../../PluginDemo/) · [编译说明](development.md#编译与架构) |

**说明：**旧版程序中的 `xiaopeng66/PulseBarPlugins` 下载地址无可访问仓库，不能把它当成有效下载渠道。本页不会用空白页面或未经核验的二进制冒充“已发布插件”。后续有正式插件发行时，应在这里增加实际发行页、支持架构、兼容版本与校验值。

## 安装

1. 从通知区菜单**正常退出** PulseBar，等待程序关闭。不要强制结束进程，否则尚未保存的流量记录或设置可能丢失。
2. 确认你要更新的那份程序目录。日常使用便携版时，目录通常是 `portable`；**不要把开发构建目录与日常运行目录混用**。
3. 将作者提供的插件 DLL 及其依赖，按作者说明放到 **正在使用的 `PulseBar.exe` 同级 `plugins` 文件夹**。
4. 启动同一目录的 `PulseBar.exe`，打开“插件管理”，检查状态是否为“加载成功”。
5. 如需在任务栏显示插件指标，在“监控项目与顺序…”中勾选插件提供的项目。

示意：

```text
日常使用目录/
  PulseBar.exe
  language/
  plugins/
    作者提供的插件.dll
```

不要把 Full 版的 `OpenHardwareMonitorApi.dll`、`LibreHardwareMonitorLib.dll` 误当作插件移动到 `plugins`；它们是主程序的硬件监控依赖。

## 使用菜单

新版托盘根菜单直接显示已成功加载的**插件名称**。展开该名称，应有：

- 详细信息；
- 选项（若插件未实现设置窗口，宿主会提示）；
- 禁用（修改后重启生效）；
- 该插件通过接口提供的自定义命令与勾选状态。

这里不再需要先进入一个额外的“插件”分类。插件内部未公开为菜单命令的功能，仍需从其选项窗口进入；宿主不能凭空生成插件没有提供的功能。

“打开插件目录”只打开当前正在使用的程序对应的插件文件夹，不是下载网站。

## 更新、停用、卸载

- **更新：**正常退出后备份原插件，再按作者说明替换 DLL/依赖，重启核对版本。
- **禁用：**在插件菜单或管理器中禁用，下一次正常启动时不加载。当前进程不会热卸载 DLL。
- **卸载：**正常退出后移走相应插件及它独有的依赖。不要批量删除其他插件共享的文件，也不要删除主程序、配置、历史流量或整个 `plugins` 文件夹。
- 不保证每个第三方插件都有自动更新索引；不要将“没有更新提示”理解为已是最新版。

## 常见问题

| 状态/现象 | 检查项 |
| --- | --- |
| DLL 加载失败 | CPU 架构、插件依赖、VC++/.NET 运行环境、系统文件阻止状态；查看宿主显示的错误码 |
| 找不到入口函数 | 插件应导出 `TMPluginGetInstance`，且导出名不可被 C++ 名字修饰改变 |
| 插件实例为空 | 插件导出了入口却没有返回对象，需要插件作者处理 |
| 插件版本不支持 | 对照本仓库接口与作者声明，不能靠重命名 DLL 修复 |
| 插件已加载但没有任务栏指标 | 在项目编辑器勾选对应显示项；纯功能型插件也可能不提供显示项 |
| 没有插件选项 | 插件可能没有实现 `ShowOptionsDialog`；这不等于主程序丢失设置 |
| 自定义命令缺少某项 | 先检查插件自身是否返回该命令。宿主会对非法/空命令与异常回调做保护，并对极端数量设置上限 |

报告问题请使用 [PulseBar Issues](https://github.com/xiaopeng66/PulseBar/issues)，提供宿主版本、插件文件名/版本、架构、错误码和复现步骤。不要公开 API 密钥、个人配置或包含私人信息的日志。
